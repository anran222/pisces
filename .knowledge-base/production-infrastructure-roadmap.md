# 生产级实验基础设施演进路线

## 背景

当前 Pisces 已具备实验管理、分流、事件采集、统计分析、AI 决策、候选变体生成、前端管理台和 SDK。下一阶段目标不是继续横向增加分析接口，而是把现有能力推进为可被真实业务接入、可审计、可回放、可降级的实验基础设施。

## 目标形态

生产级实验基础设施按四个平面演进：

| 平面 | 职责 | 当前对应模块 | 生产级目标 |
| --- | --- | --- | --- |
| Control Plane | 实验配置、生命周期、权限、审计、配置发布 | `pisces-api`、`ExperimentService`、`ConfigService` | 配置版本化、可回滚、可审计，管理接口有权限边界 |
| Data Plane | 在线分流、规则命中、SDK 本地缓存、降级 | `TrafficService`、Java/JS SDK | 低延迟稳定分流，依赖异常时基于配置快照降级 |
| Event Plane | 曝光与事件采集、幂等、异步处理、指标聚合 | `DataService`、事件/曝光 Repository | 采集入口快速确认，事件可去重、可重放、可回算 |
| Decision Plane | 数据质量、统计分析、AI 诊断、报告快照、人工结论 | `AnalysisService`、`AIDecisionService` | 结论绑定配置版本与指标快照，AI 只消费可信事实 |

## 阶段推进

### 阶段一：准生产内核

目标：在当前单体内收紧安全、配置、数据链路和主流程验证，为后续拆分打基础。

交付物：

- 清理仓库中的敏感默认配置，数据库密码、通义 API Key、管理 API Key 均从环境变量注入。
- 明确本地启动所需环境变量和 AI 能力的失败行为。
- 建立真实实验闭环验证：创建实验、启动实验、分流、曝光、事件、统计、AI 决策。
- 前端展示数据链路状态：分流数、曝光数、事件数、分析是否就绪。
- 补齐 Service 层或端到端 smoke test。

验收标准：

- 无真实密钥或固定 API Key 默认值留在仓库配置中。
- 未配置 AI Key 时，普通实验管理链路可运行，AI 接口给出明确错误。
- 一个新实验可以按文档完成真实接入并看到可信分析状态。

### 阶段二：事件采集异步化

目标：把事件采集从同步服务内处理演进为可靠事件管道。

交付物：

- `/data/event` 与 `/data/exposure` 变为采集入口，先完成请求校验和幂等键受理。
- 引入消息队列或内部事件日志作为原始事件缓冲层。
- 后台消费者异步落库、聚合、去重。
- 明确 `clientEventId`、`assignmentId`、`exposureId` 的幂等和关联规则。
- 指标计算支持基于原始事件重放。

验收标准：

- 事件上报接口能承受业务侧重试，不产生重复计数。
- 原始事件、曝光、分流记录可以串联追踪。
- 指标聚合结果可通过重放修正。

### 阶段三：在线分流平面拆分

目标：把低延迟分流能力从管理链路中隔离出来。

交付物：

- 分流运行时只依赖配置快照和本地/Redis 缓存。
- SDK 支持本地配置缓存和配置版本识别。
- 配置发布采用版本拉取或推送模型。
- 规则分流输出命中原因，便于排查。
- 依赖 Redis、Zookeeper 或 MySQL 异常时，分流可降级到最后可用快照。

验收标准：

- 分流热路径不依赖管理端实时读写。
- 配置变更后用户跳组行为可解释。
- 关键依赖短时不可用时，线上分流不整体失败。

### 阶段四：治理平台化

目标：支持多业务、多应用、多负责人协作。

交付物：

- 增加应用/项目空间。
- API Key 归属于应用。
- 实验归属于应用和负责人。
- 管理操作写审计日志。
- 支持实验层、互斥冲突检测、审批流。
- 建立事件字典和指标字典，支持实验定义沉淀为应用级资产。

验收标准：

- 不同应用的配置、数据、权限互相隔离。
- 实验配置、启动、停止、结论确认都有审计记录。
- 管理台可以按应用、状态、负责人筛选和治理实验。

## 约束

- 不直接拆微服务。先在单体内明确边界和契约，再拆分热路径。
- AI 不自动变更实验状态。AI 输出会被数据质量门禁修正，结构化响应必须携带可审计证据。
- 生产级推进优先保障数据可信度，新增统计方法不是当前优先事项。
